Why Strong Passphrases Matter for PGP

Your PGP private key is only as strong as the passphrase protecting it. If an attacker obtains your privateKey.txt file, they can attempt to crack the passphrase offline. This generator uses your browser's cryptographically secure crypto.getRandomValues() API—never Math.random()—to produce unpredictable passwords and Diceware-style passphrases.

Random Passwords vs. Diceware Passphrases

Random character strings (16–24+ characters) are ideal for password managers and symmetric encryption in PGP File Encryption. Multi-word passphrases (6+ random words) are easier to type from memory when unlocking your PGP key in OnlinePGP.com or GnuPG.

Best Practices

Never reuse a PGP passphrase on any website. Store it in a dedicated password manager, and aim for at least 60–80 bits of entropy. Read How to Generate a PGP Key Safely and Common PGP Mistakes, or browse all security tools.

Frequently Asked Questions

Is crypto.getRandomValues() truly random?

Yes. It uses your operating system's cryptographically secure random number generator (CSPRNG).

Are generated passwords ever logged or sent?

No. Everything runs locally in your browser.

How many words should a PGP passphrase have?

At least 5 to 6 random words, or a 16+ character random password.

What does entropy in bits mean?

Entropy measures how hard a password is to guess; each extra bit doubles the number of possible combinations.
